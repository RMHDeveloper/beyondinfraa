## 2026-09-04 - Production-readiness security/reliability fixes
Following a production-readiness audit (senior-engineer + business-analyst review), fixed the blockers that don't depend on the upcoming Firebase Phone Auth migration (that migration will replace OTP generation/delivery specifically — tracked separately, pending Firebase Web SDK config from the user):

- **Cron auth gap**: `app/api/cron/followup-reminders/route.ts` and `app/api/cron/site-visit-reminders/route.ts` only checked `x-cron-secret` when `NODE_ENV === "production"` — meaning any non-Vercel/misconfigured deploy ran these with zero auth. Now both routes always require a matching `CRON_SECRET` (fails closed if the env var is unset), regardless of `NODE_ENV`.
- **Unescaped HTML injection in outbound emails**: added `escapeHtml()` to `lib/mailer.ts` and applied it to every user/staff-editable string interpolated into email HTML — `clientName`/`projectTitle`/`staffName`/`location`/`description` across the three existing template functions, and the compose-your-own-email `body` in `app/api/projects/[id]/bulk-marketing-ppt/email/route.ts`. Previously a staff user (or a compromised staff session) could inject arbitrary HTML/links into emails sent to real clients under the BeyondInfra name.
- **OTP dev-bypass not environment-gated**: `app/api/client/otp/route.ts` used `OTP_DEV_BYPASS` unconditionally if the env var was set, not gated by `NODE_ENV`. Now it's only honored when `NODE_ENV !== "production"` — safe even if the var leaks into a prod `.env`.
- **OTP brute-force protection**: added `ClientLink.otpAttempts` (migration `add_missing_fk_indexes`, applied alongside the index migration below). `verify-otp/route.ts` now locks out after 5 wrong guesses (requires a fresh OTP request to reset), and `otp/route.ts` enforces a 60s cooldown between OTP (re)issues so the attempt counter can't be reset by spamming new OTP requests.
- **Missing `.env.example`**: added, listing every var actually read by the app (cross-checked against the real `.env`), with placeholder values and a note on `OTP_DEV_BYPASS`'s dev-only behavior.
- **Missing FK indexes**: the schema had zero `@@index`/`@index` directives on any foreign key (Postgres does not auto-index FKs). Added `@@index` to every FK column not already covered by a `@unique`/`@@unique` prefix, across `Project`, `AuditLog`, `Response`, `Match`, `Proposal`, `SiteVisit`, `Deal`, and ~15 other models — migration `add_missing_fk_indexes`. Addresses sequential-scan risk on joins/lookups as data grows (dashboard, matching engine, audit log tab were the most exposed).
- **Hardcoded Vercel URL fallback**: `lib/storage.ts`'s `APP_ORIGIN` hardcoded a specific `beyondinfraa-k9zk.vercel.app` domain as the production fallback. Now reads `NEXT_PUBLIC_APP_URL` (already present in `.env`), so it no longer silently breaks if the app moves to a different domain/Vercel project.

`npx prisma migrate dev --name add_missing_fk_indexes` applied cleanly, `npx prisma generate` run, `npx tsc --noEmit` clean (exit 0).

**Explicitly deferred, not fixed in this pass** (per user direction — full Firebase OTP migration is a separate follow-up once Firebase Web SDK config is provided): OTP generation/delivery still uses the original random-6-digit + no-SMS-send (dev echoes it in the response) flow, now hardened as above but not yet replaced by Firebase Phone Auth.
